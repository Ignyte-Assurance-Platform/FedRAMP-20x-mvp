# Fool-proof checklist (walk it before exporting)

- [ ] I read the brief as the reviewer, who has never seen the tool, the mockup or the spec. Every sentence makes sense on its own.
- [ ] Every tool, file, folder, spreadsheet tab, screen, button, person's work and version mentioned is in "Words used", with where to see it and whether it is real yet.
- [ ] No word means two things (watch "tab", "form", "file", "link", "version").
- [ ] Every screen discussed has a screenshot with a caption: which screen, which mockup, what to look at, what to ignore, example data is made up.
- [ ] Every difference between the mockup and what we will build is stated next to the screenshot.
- [ ] On-screen labels are quoted exactly as they appear.
- [ ] Their own work is named exactly (file, sheet tab, folder, date).
- [ ] No technical words, no shorthand symbols, no unexplained acronyms (`lint-brief.mjs` passes).
- [ ] One decision per numbered point, two sentences at most.
- [ ] Every question offers options and states the default if unanswered.
- [ ] "Not in this first version" lists what a reader might otherwise assume.
- [ ] Coverage table maps every behaviour and acceptance criterion of the source; nothing added that the source does not say.
- [ ] Reading time at the top is honest.
- [ ] I opened the exported Word file and looked at every page.
